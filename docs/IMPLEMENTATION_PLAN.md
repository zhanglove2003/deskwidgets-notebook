# DeskWidgets 修复与图文笔记执行方案

> 日期：2026-11-01。交付物是执行方案，尚未修改组件代码。
> 执行者：按任务逐项实施。若由编码代理执行，可使用 superpowers:executing-plans；不要求使用子代理。

**目标：** 修复切图延迟、重启错位和右侧无法使用的问题；将现有相册扩展为支持章节筛选的图文笔记。

**架构：** 保留 DeskWidgets、conky 和现有 album 实例。Lua 负责桌面卡片和翻页；Python 负责持久数据、图片缓存和 GTK4 编辑窗口。服务端单独修复网格定位，避免将布局问题混入笔记数据。

**技术：** Python 3、PyGObject GTK4、Pillow、Lua/Cairo、X11。继续使用当前系统依赖。

**需求来源：** 用户本轮描述及已讨论方案；环境说明见同目录 HANDOVER.md。本文同时给出具体设计和实施步骤。

## 全局约束

- 不添加探针、鼠标模拟脚本或自动化测试。只做语法、加载检查及用户实操验收。
- 保留当前图片、便签、翻译设置和已有组件实例。不要恢复交接文档中的旧布局覆盖当前布局。
- 保留中文界面和 200% 缩放适配。X11 使用物理像素，网格内部使用逻辑像素；转换只发生在边界。
- 修改 layout.json 前必须停止服务，否则内存布局可能覆盖文件。
- 笔记正文、章节、阅读位置必须持久保存；/run/user/1000/deskwidgets 只保存可重建的缓存。
- 不要求更换桌面框架、启用 GNOME 扩展、注销会话或新增网络服务。
- 不在现有 /home/snow/.codex/visualizations/2026/11/01/01a196e0-e4a0-7a83-a9a5-3e3f6bb7a612 或 /mnt/data/project-ai/liunx 项目里实现本功能。

## 当前证据与边界

1. album/widget.json 中 interval=10；engine/widget.conf 将其作为 conky 的 update_interval。滚轮处理只更新 idx，没有请求即时重绘。事件已到达而画面等待刷新，有明确代码依据。
2. png_for() 到绘制当前图片时才启动转换；topng.py 转换整张原图。图片缓存仅用文件名截断键，存在跨目录碰撞和源文件更新后缓存不刷新的风险。
3. service.py 的 poll() 将首次窗口位置与 requested 的差值永久接受为 offset。启动落点错误会被吸收；后续 settling 分支也可能接受较大偏移。
4. 当前屏幕 2560×1440，缩放 2。网格逻辑宽度 1280，六列宽 1100，x0=90，因此右侧自然留下 180 个物理像素。尚未证明有其他窗口遮挡。
5. 当前相册是 medium，即 2×1 格。默认 170 逻辑像素高度不适合同时阅读图片和长笔记。

- [ ] 记录当前 deskwidgets list 输出、屏幕尺寸、DPI 和各实例尺寸、格位。当前数据优先于 HANDOVER.md 的历史记录。

交付：原始文件均可恢复，且明确知道此次改动的文件清单。

### 任务 2：消除翻页等待

**修改：** album/widget.json、widget.lua、topng.py。

- [ ] 将 album 的 interval 从 10 改为 0.1 秒。目录扫描仍保持独立的 10 秒节流，不能每帧扫描。
- [ ] 首次读取目录后，后台预先转换当前、下一张和上一张。不要等翻页后才第一次开始转换。
- [ ] 同一个缓存键只允许一个转换任务；失败任务保留错误和短暂重试间隔，不能每 0.1 秒启动 Python。
- [ ] 缓存键改为完整规范路径、源文件 mtime_ns、文件大小、目标像素尺寸和转换版本的 SHA-256。避免文件名相同、中文截断和原图更新导致错图。
- [ ] 使用 Pillow 的 EXIF 方向校正与 thumbnail()，输出尺寸按实际卡片物理尺寸生成，保留原图。临时文件使用唯一名称，成功后 os.replace()。
- [ ] 缓存存在检查不读取整张 PNG；绘制时复用已加载 surface。缓存键变化后释放旧 surface。
- [ ] 将当前图片序号改为按图片身份保存，写文件使用原子替换；这一持久状态在任务 5 迁移到条目 ID。
- [ ] 保留真实 conky 1.19 事件格式：mouse_scroll，direction=up/down。向下为下一条，向上为上一条。已处理事件返回 true。

验收：预热完成后，用户滚动一次能看到立即翻页；连续滚动不再等待数秒，不出现每帧重复转换。首次尚未准备好的图片有清楚的加载提示。

### 任务 3：修复启动位置被永久吸收

**修改：** service.py 的 Runner.start()、move()、poll()。

- [ ] 将生命周期明确分为启动定位、正常跟踪和程序移动后的稳定等待。每次 start() 清零 cooldown、still、settling 和旧 offset，避免 reload 继承旧状态。
- [ ] 首次发现窗口后，先把窗口移动到保存格位对应的位置，再观察稳定位置；不要直接把初始误差作为 offset。
- [ ] offset 只容纳窗口管理器的微小装饰误差，建议每轴不超过 4 个逻辑像素。超出范围时重新定位，不能写回新的布局格位。
- [ ] 程序移动后的稳定等待也使用相同偏移上限。重复被窗口管理器限制时，保留原保存格位并给出一条现有日志渠道的错误说明，停止无限移动；不要把错误位置冒充用户拖拽保存。
- [ ] 只有窗口已经完成启动定位、没有程序移动等待，并且实际经过位置变化和停止过程，才进入现有拖拽吸附逻辑。
- [ ] 清理 do_activate() 中重复的 load_settings() 调用，以及 x11.py 中重复定义的 dpi_factor()；保留一份原有有效实现。

验收：由用户先拖动几个组件，再执行 reload 和完整退出重开。每个组件恢复到保存位置；不得因启动错位自动改变 col/row。

### 任务 4：让最右侧格位贴近屏幕边缘

**修改：** grid.py、service.py、所有位置调用者；必要时同步扩展。

本次选择“保留组件尺寸，为最右侧组件提供边缘落点”。不通过放大组件来填满留白，也不把额外空间平均分散到所有卡片间。

- [ ] 在 Grid 内保留 screen_w、side 和明确的 card_xy(col, row, size)；window_xy(col, row, size) 在卡片位置上减去透明阴影 margin。
- [ ] 左侧起点使用 side；普通列按原 pitch 排列。当 col == cols - 组件占列数时，该组件卡片 x 使用 screen_w - side - card_width。两列网格中占满整行的组件使用左侧起点，避免左右条件冲突。
- [ ] 对 small、medium、large 分别使用自身宽度计算右缘。不要用“最末列坐标”直接定位一个占两列的组件。
- [ ] nearest_cell() 不再单纯用 round((x-x0)/pitch)。枚举该尺寸所有合法格位，使用与 window_xy() 相同的坐标计算最近落点，随后按已占用格位过滤。
- [ ] 更新 service.py 中所有 window_xy() 调用，传入 size；启动、移动、位置比较和吸附必须共用同一套坐标函数。
- [ ] 网格 JSON 提供各实例的实际逻辑卡片矩形及每种尺寸的合法落点。若 GNOME 辅助扩展仍使用 x0+col*pitch，改为读取这些矩形和落点，再按照扩展坐标系正确转换 DPI。
- [ ] 当前扩展未启用也不要求启用，但不能留下启用后吸附到旧坐标的已知不兼容。
- [ ] 检查所有合法且格位不相交的组件，在新坐标下也不会发生可见卡片重叠；透明阴影不作为卡片宽度计算。

验收：最右组件距屏幕右缘为 margin_side=24 个逻辑像素，即当前缩放下 48 个物理像素；不再有原来的 180 像素固定留白。用户拖拽后重启，位置保持。

## 第二部分：扩展为图文笔记

### 任务 5：建立持久数据和兼容迁移

**新增：** notebook.py、实例数据目录。

数据约定：

```json
{
  "version": 1,
  "revision": 1,
  "chapters": [{"id": "ch-uuid", "title": "未分类"}],
  "entries": [{
    "id": "entry-uuid",
    "chapter_id": "ch-uuid",
    "title": "山与月",
    "image": "images/entry-uuid.png",
    "body": "",
    "order": 0
  }]
}
```

阅读状态单独保存：

```json
{"version": 1, "chapter_id": null, "entry_id": "entry-uuid"}
```

chapter_id=null 表示全部章节；“全部章节”不是一个真实可编辑章节。条目 ID 和章节 ID 创建后不随重命名变化。

- [ ] 定义 load_book(root)、save_book(root, book, expected_revision)、load_view(root)、save_view(root, view) 四个 Python 接口。保存采用同目录唯一临时文件和原子替换；笔记保存使用文件锁和 revision 检查。
- [ ] 旧目录迁移只在 notebook.json 尚不存在时运行。按现有文件名顺序建立条目，标题取去扩展名后的文件名，章节为“未分类”，正文为空；把图片复制进 images/，不改动原目录。
- [ ] 迁移全部成功后才提交 notebook.json。失败时保留原相册可读状态，显示可理解的错误，不创建一个假装迁移完成的空库。
- [ ] 若旧 .idx 可读，映射为对应条目 ID；不存在或越界时选第一条。今后阅读状态不依赖临时目录。
- [ ] 空笔记库支持创建第一条。损坏的 JSON 不得静默覆盖为空库；保留原文件并在编辑窗口显示错误。
- [ ] 删除章节时，将条目移到“未分类”；删除条目需在编辑窗口确认，只删除数据引用，首版不自动清理图片文件。

验收：原有三张图片成为三条记录，原图片仍存在；退出服务、清除运行缓存或重新登录后，记录和阅读位置保留。

### 任务 6：明确 Python 与 Lua 的显示接口

**修改：** notebook.py、widget.lua。

避免在 Lua 中临时拼 JSON 或依赖尚未确认安装的 JSON 库。Python 为 Lua 输出 UTF-8 展示快照：

```text
<运行目录>/album-<安全实例键>/snapshot/
  generation
  chapter.txt
  count
  selected
  entries/1/id
  entries/1/title.txt
  entries/1/body.txt
  entries/1/image.png
```

其他条目按 entries/2、entries/3 编排。generation 是本次快照版本；image.png 是准备好的显示缓存，可在转换完成后原子替换。

- [ ] notebook.py 提供 prepare --instance ID --folder PATH --width PX --height PX 命令：载入或迁移、按章节过滤、排序、建立完整快照。先准备独立版本目录，再原子切换 current 符号链接，Lua 每次读取先解析固定版本，避免混读。
- [ ] 提供 select --instance ID --entry ENTRY_ID 命令：只写 view.json，不重写正文库。翻页显示立即发生，持久化以短暂合并写入方式保存最后选项，避免每个滚轮事件都启动进程。
- [ ] 提供 refresh 与章节变更路径：编辑保存或章节切换后重建快照；Lua 只在 generation 改变时重新读取标题和正文，不在每帧读完整内容。
- [ ] 所有命令参数使用现有 L.quote/L.python 的安全参数传递方式，章节名、标题和正文不拼接进 shell 命令。
- [ ] 保留当前与相邻图片优先转换。数量多时其余条目排队；只有一个后台队列处理缓存，不启动无上限的转换进程。
- [ ] 旧快照清理保留当前与上一版本，并避开仍在转换的目录。服务重启后可从持久库重建所有快照。

验收：改正文只改变对应条目；改章节立即影响当前列表；文件名包含中文、空格或引号时仍能显示。

## 用户实操验收清单

1. 当前条目向下滚动到下一条，再向上回去；重复几次，观察是否立即响应。
2. 新建两个章节，每章加入不同图片和笔记；切换章节后只出现该章内容；“全部章节”可以看全。
3. 编辑中文长正文，保存后卡片有预览，重新打开能阅读完整内容。
4. 添加无图片笔记、空章节，以及名称含空格的图片，检查界面和错误提示。
5. 把组件拖到最右侧，确认距屏幕边缘只保留设置边距；拖动其他组件，确认无可见重叠。
6. 执行 reload，再完整退出重开；检查组件格位、当前章节、当前条目和笔记内容。
7. 确认翻译、便签、天气、日历等现有组件仍可使用。

由用户反馈“通过”后，才将相应项目标为验收完成。不用脚本代替用户滚动、点击或拖拽。

## 回滚
